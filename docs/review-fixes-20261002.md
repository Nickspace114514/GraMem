# 四项审查问题修复（2026-10-02）

本次修复针对当前本地 GraMem 2.0.2 源码，不修改生产记忆、配置或服务。

| 问题 | 修复结果 |
|---|---|
| 压缩时把所有历史用户消息归给当前作者 | 只交接本会话已核实的消息，逐作者分组。机器人、未核实历史及多作者相同文本的歧义消息跳过，切换会话清空映射。正常 sync_turn 的持久采集保持不变。 |
| 模型工具可以在无用户意图时删除、停用或恢复记忆 | 自动语义核对当前消息、具体操作与目标。明确请求直接执行，不新增确认步骤；范围含糊返回 clarification_required。同轮已核实判断复用，无固定关键词要求。候选确认/拒绝也核对当前意图。 |
| 文档遗忘后重叠内容仍可从相邻分块召回 | 以文档来源为清除单位，覆盖全部重叠分块、绑定事实与传递派生内容；同时清除索引、向量、原文及相关图记录。其他文档与身份保留。新旧记录均适用，包括重复事实的次要来源链。 |
| 合并文本与一个原事实相同时提前去重并报告成功 | 创建合并版本并使全部目标失效，保存来源链；普通重复 ADD 和单例原值重复保存仍复用原记录。 |

文档来源范围已写入 Agent 提示、接口手册、管理面板说明及其原有遗忘确认文案。遗忘一个分块会清除整份关联文档来源，不提供文档内局部擦除。重新授权不会恢复旧文档。

测试额外暴露了并发打开 SQLite 时 journal_mode 切换的偶发 BUSY。增加 15 秒以内的有限重试，非 BUSY 错误立即失败并关闭连接；原有并发迁移用例连续 20 次通过。

验证：114 项本地测试通过；核心、脚本与附属 Python 组件通过 ruff；面板 JavaScript 通过语法检查。新增用例覆盖作者隔离、同轮授权复用、无关键词请求、引用/纠正拒绝、原话证据、含糊范围、模型不可用、恢复与候选控制、文档来源隔离和合并来源链。

意图分类测试使用受控模型响应，验证执行边界及提示输入；没有在本次修改中调用真实模型、连接生产 FalkorDB 或运行服务器验证脚本。语义理解仍依赖配置模型，不能保证零误判。
