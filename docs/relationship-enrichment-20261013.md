# 关系提取补齐（2026-10-13）

线上调查：77 条有效记忆中仅 13 条附带关系；图服务有 11 条原始 FACT 边，来源校验后查询返回 7 条。图同步队列无积压。因此问题包含提取覆盖不足，而非图服务完全失效。

显式 remember/面板保存路径不自动提取关系，自动提取允许空关系；原先没有任何后台补齐机制。新增 `gramem.relations.Relations`，由知识 worker 每轮检查一条可用有效记忆，覆盖历史及新增事实。模型只读取已接受事实和其证据，关系端点要求原文名称；第一人称可用“用户”。不从共同出现推断关系，不翻译名称。主提取提示覆盖人物、组织、地点、产品、偏好、所有权及项目依赖。

处理标记存在记忆 metadata.relation_extraction；revision=1 表示完成（含无关系事实），retry_at 是 300 秒租约/重试时间。已有关系保留，新关系去重并走原生 graph_outbox。模型调用外不持有数据库事务；提交前重查版本、身份排除 epoch、当前有效性和来源控制。遗忘或停用不允许恢复关系。错误仅记录异常类型，不记录事实正文。

部署前备份 `<HERMES_HOME>/backups/relations-20261013/` 中的 SQLite、engine.py 和知识 worker；同步三个源码文件，重启 Gateway、面板及知识 worker。后台逐条处理历史，费用使用现有 GraMem 模型配置。

验证：50 项相关回归通过，4 项真实 FalkorDB 环境测试未在本机运行；修改文件 ruff 检查通过。线上三服务已恢复 active，首条补齐已完成，图队列无积压。历史补齐进度可从 metadata.relation_extraction.revision 统计。
